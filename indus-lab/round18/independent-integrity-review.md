## Exact joins and alias checks

Only M-1547 joins the selected CSV by its CISI identifier, through records3787.1 and3787.2. A second search covered every string field with case-insensitive M-prefixed identifiers, optional whitespace/dash variants/underscore/dot/slash separators, leading zeros, optional face letters, and numeric boundaries. It found only those same two rows. A broader numeric-only search additionally found H-1544/1545/1546/1547, database IDs1543.1–1547.1, and unrelated fields on M-1847 andM-491. Those are not legitimate aliases for M-1543–1546: site prefix and identifier namespace must be preserved.

Absence of a recognizable identifier in this CSV does not prove absence under an unrecorded excavation/collection alias, from another corpus, or from a published catalogue. This audit has not exhaustively resolved historical aliases across all editions. Exact-match nonmembership is the justified finding.

Therefore the pilot does **not** add four newly readable inscriptions. It adds catalogue-linked photographs for four objects without a recognized join in this particular CSV, plus paired images for one joined object. All five were already published in CISI. Poor or indistinct photographs may support neither a complete sign count nor a sequence; null remains appropriate. M-1547's imported strings, including +753+, are prior transcription assertions, not confirmations derived from these photographs.

## Implementation assessment

No blocking extraction defect found. Source identity is pinned before output; crop operations neither enlarge nor enhance; face uncertainty and manufacturing independence are explicitly retained. One minor hardening opportunity: validation.json's every_object_has_A_and_B is generated by checking two faces per object, rather than explicitly checking the set {A,B}. The current actual data passes the stronger independent set check, so no repair is required for this pilot. If generalized, test the actual labels as well as counts.

Reproducibility caveat: source.json records the PDF URL and hashes, while imported assertions record the CSV hash but not its repository commit or remote URL. The lab's existing provenance manifest should travel with a shared package. The present checks verify current bytes and links, not the CSV's scholarship or licensing.

The next reviewable advance would be independent photographic transcription or explicit abstention with confidence and damage masks, followed by reconciled catalogue aliases and production-family grouping. A/B pair availability alone does not establish image-sign meaning, a new translation, or statistically independent observations.
